# Terminal interaction design

The human is a bookkeeper or owner reviewing their work at a terminal. They need
to select an account, enter exact amounts, inspect a proposed effect, and establish
what durably happened. The feel is a dense ledger folio: quiet, aligned and legible.

The domain vocabulary is journals, debit/credit columns, posting sequences, account
charts, fiscal periods, correction links, tied statements and retained receipts.
Its color world comes from paper, ink, graphite rules, green verification marks,
amber pending slips and red correction ink. Terminal background preferences remain
in control. Muted graphite separators and one restrained ink accent provide
structure; color adds emphasis to text status and never carries meaning alone.

The signature is a visible accounting scope line and the draft → review → receipt
sequence. Book/currency appear above each area. Reports carry date, basis, revision
and population into activity and journal details. Review shows the command identity,
content hash and exact effects; the receipt shows its durable disposition.

Three defaults were considered: a dashboard of metric cards, color-only success
indicators and a separate wizard for every mutation. Aligned financial tables,
written statuses and shared field/review components serve these bookkeeping tasks.
At narrow widths rows become stacked records, preserving full amounts. Wide views
show account or period details alongside the selected row. Unicode cell widths and
keyboard focus matter more than ornamental framing.

Navigation uses five numbered work areas, with local modal forms and persistent
connection context. Draft saving is separate from financial submission. A pending
request locks dependent controls; cancellation records an uncertain result and
offers inspection/resume under the original identity. No modal changes book scope.

The terminal is presentation only. It transports decimal strings and renders
server results; it does not reproduce posting, balance or period rules. Bubble Tea
owns terminal lifecycle; Bubbles owns text entry/scrolling; Lip Gloss owns quiet
typography and emphasis. Headless JSON remains the accessible automation surface.
